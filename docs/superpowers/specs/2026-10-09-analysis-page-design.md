# 分析ページ（中切れ可視化）設計書

- 作成日：2026-10-09
- 対象バージョン：v3.0.0（予定）
- 対象プラットフォーム：**PC ユーザースクリプト（React 版オーバーレイ）のみ**。ブックマークレット / iOS / Android は対象外（後続検討）。

## 1. 目的

クリテリウムなど周回レースで、**集団の分断（中切れ）が「いつ」「どの選手の間で」起きたか**を可視化する。FastF1 のような周回単位の分析（先頭差推移・順位推移・ラップタイム比較）を、LapClip を閲覧中のブラウザ内だけで行う。

成功基準：2026 佐世保クリテリウム（`evt=tdk2026&ctg=100`）で、次の分断・合流が画面上で読み取れること。

- L5：後方 10 名が +31.8 秒で分断
- L7：メイン集団が 56 / 28 / 8 / 8 に分断（切れ目：No.131 と No.11 の間）
- L17：先頭集団から 8 名が抜け出し（+5.5 秒）
- L22：周回遅れ 28 名の除外
- L25：再合流（31 名）
- L28：No.91 の単独先行

（上記はしきい値 3 秒での事前検証結果。）

## 2. 権利・データ取扱いの方針

- 取得対象は**閲覧中ページと同一オリジンの公開ページ**（`result.php`・`laptimes.php`）のみ。
- 取得は**ユーザーが「分析を読み込む」を押したときだけ**。自動更新・定期取得はしない。
- **1 件ずつ・250ms 間隔**の逐次取得（100 名で約 30 秒、実測）。並列取得はしない。
- 結果は**メモリ上のみ**。localStorage / IndexedDB / 外部送信・エクスポート機能は作らない。
- README の「fetch は一切なし」の記述は、v1.2.0（チームTTの `laptimes.php` 取得）以降すでに実態と食い違っているため、本対応で「閲覧中サイトと同一オリジンの公開ページを、ボタン押下時にブラウザ内で読み取るだけ（保存・送信なし）」に改める。

## 3. 入口と有効条件

- オーバーレイのヘッダーに **[タイミング] [分析]** のタブを追加する。
- 分析タブは `raceShape === 'mass_start'` かつ先頭の周回数が 3 周以上のときに有効。それ以外は理由を表示して無効化する。

## 4. データ取得（`src/analysis/fetchLapHistory.ts`）

### 4.1 選手リスト

1. 表示中ページの `a.result` 行から bib を取得。
2. `result.php?evt=…&ctg=…&page=2,3,…` を、取得行数が 100 未満になるまで逐次取得し、bib を追加（佐世保：page=2 に 101〜106 位の 6 名）。
3. bib の重複は除く。

### 4.2 ラップ

- 各 bib について `/lap/laptimes.php?evt=…&ctg=…&num={bib}` を逐次取得。
- 行構造：`td.syukai`（周回番号 or `FINISH`）・`td.juni`（その周の通過順位）・`td.lap`（ラップタイム）・`td.total`（累計タイム）。
- 解析処理は既存 `src/userscript/fetchLaptimes.ts` の行解析と共通化する（共通の行パーサーを切り出し、チームTT側もそれを使う）。

### 4.3 進捗・中止・失敗

- 進捗（取得済み / 総数）をコールバックで通知。`AbortSignal` で中止可能。
- 個別ページの取得失敗は、その選手を「データなし」として続行し、件数を画面に表示する。

### 4.4 データ形

```ts
type LapPoint = { cumMs: number; pos: number | null; lapMs: number | null }
type RiderLapHistory = {
  bib: string
  name: string
  teamCode: string | null
  laps: Map<number, LapPoint> // 周回番号 → 通過記録。FINISH は最終周回番号
  finished: boolean           // FINISH 行がある
}
type LapHistory = {
  riders: RiderLapHistory[]
  lapNumbers: number[]        // 1 名以上の記録がある周回番号（昇順）
  missingLaps: number[]       // 1..最終周の範囲で全員の記録が無い周回番号
  failedBibs: string[]
}
```

- **FINISH の周回番号**：その選手の最大周回番号 + 1。全完走者で同じ値になる（佐世保：30）。

## 5. 判定ロジック（`src/analysis/groups.ts`・純粋関数）

### 5.1 周回ごとの集団分け

- 周回 L の通過記録を累計タイム昇順に並べ、前の選手との差が**しきい値以上**の所で区切る。
- しきい値：**初期値 3 秒**、画面のスライダーで 1〜10 秒（0.5 秒刻み）。
- 出力：`Group = { lap, riders: bib[], frontGapMs /* 先頭集団との差 */, spanMs }`

### 5.2 計測漏れ

- **全員欠損の周**（佐世保の 2 周目）：`missingLaps` に入れ、判定・描画の対象外。図では点線の隙間として示す。イベント検出は欠損周をまたいで前後の周を比較する。
- **一部選手のみ欠損**：その選手をその周の集団分けから除外する（補間しない）。

### 5.3 集団の追跡とイベント

連続する計測周 P → L（欠損周はスキップ）で、各集団をメンバーの重なりで対応づける。

- **分断**：P の 1 集団のメンバーが、L で 2 つ以上の集団に分かれた。
  - 隣り合う各切れ目について、**A = 前側の最後尾**、**B = 後側の先頭** を記録する。B を「前の選手の後輪に付ききれなかった選手」として強調表示する。
  - 種別：
    - **抜け出し**：前側の人数 < 後側の人数
    - **脱落**：後側の人数 ≤ 3
    - **中切れ**：上記以外
    - （抜け出しと脱落の両方に当てはまる場合は、前側が小さければ抜け出しを優先）
  - 判定対象は「P で同じ集団だった選手」に限る（P で既に別集団だった選手は対象外）。
- **合流**：P の 2 集団以上のメンバーが、L で 1 集団にまとまった。
- **除外**：P に記録があり、L 以降に一度も記録が無く、完走していない選手 → L で除外（DNF）。同じ周の除外はまとめて 1 イベント。
- **経過**：分断イベントごとに、以降の周での A–B 間の差（A・B が別集団のままの間）と、同集団に戻った周を記録する。
  - 翌計測周で合流した分断は **一時的** フラグを付ける。

```ts
type SplitKind = '中切れ' | '抜け出し' | '脱落'
type RaceEvent =
  | { type: 'split'; lap: number; kind: SplitKind; a: string; b: string;
      frontSize: number; rearSize: number; gapMs: number;
      followUp: { lap: number; gapMs: number }[]; rejoinedLap: number | null; transient: boolean }
  | { type: 'merge'; lap: number; size: number; fromGroups: number }
  | { type: 'pulled'; lap: number; bibs: string[] }
```

### 5.4 表記上の注意（画面に明記）

- 計測はフィニッシュラインで周 1 回のため「L 周目の途中で発生（L 周目通過で確認）」と表記する。
- 通過順は原因を断定しないため、A / B は「切れ目の前後の選手」と表記する。

## 6. 画面構成（`src/components/analysis/`・自前 SVG）

```
[タイミング] [分析]
┌ 分析を読み込む ▶ ┐ 進捗 ███░░ 62/106  [中止]   取得失敗 0
しきい値 ──●──── 3.0秒
├──────────────────────────────────────────────┤
│ ① 集団タイムライン（全幅）                           │
├───────────────────────┬──────────────────────┤
│ ② 中切れイベント一覧        │ ③ 順位推移               │
│                            ├──────────────────────┤
│                            │ ④ ラップタイム推移        │
└───────────────────────┴──────────────────────┘
```

- **① 集団タイムライン**（`GroupTimeline.tsx`）：横 = 周回、縦 = 先頭集団との差（秒、下向きに増加）。各周の集団を縦の帯で描き、帯の太さ = 人数。分断 ◆ / 合流 ● / 除外 × のマーカー。選択選手は線で重ね描き。帯ホバーでメンバー一覧と人数。欠損周は点線の隙間。
- **② イベント一覧**（`SplitEventList.tsx`）：周回順。例「L7 中切れ 56｜28　A No.131 ⇢ B No.11　+18.8s → L8 +18.6s（持続）」。「持続のみ」切替。行クリックで①の該当周をハイライト、A / B クリックで選手選択。
- **③ 順位推移**（`PositionChart.tsx`）：横 = 周回、縦 = 通過順位（`td.juni`）。選択選手は色線、他は薄い灰線。
- **④ ラップタイム推移**（`LapTimeChart.tsx`）：選択選手のラップタイム比較。
- **選手選択**：既存の ★ 注目選手と連動。最大 5 名を色分け（6 名目以降は ★ のまま灰色）。
- **共通部品**：`svgAxis.tsx`（軸・目盛・グリッド）。
- **スタイル**：既存の Tailwind ダーク調に合わせる。
- **状態管理**：`AnalysisView.tsx` が取得状態・LapHistory・しきい値・選択・ハイライト周を保持。集団分けとイベントはしきい値変更時に `useMemo` で再計算（取得のやり直しは不要）。

## 7. プレビュー・テスト

- SPA 版に `?mock=analysis` を追加。架空データで分析画面を取得なしで確認できる。
- 単体テスト（Vitest）：
  - `laptimes.php` 行パーサー（周回・FINISH・欠損・不正行）
  - 選手リストのページ送り（100 行未満で停止）
  - 集団分け（しきい値境界：ちょうど 3.000 秒は区切る）
  - 分断・合流・除外・一時的・計測漏れ周のスキップ・一部欠損選手の除外
  - 種別判定（中切れ / 抜け出し / 脱落）
- テストデータは既存方針どおり**架空の選手・タイム**（書式のみ模倣）。実データはリポジトリに保存しない。
- 実データでの受け入れ確認：佐世保クリテリウムで §1 の成功基準を目視確認（取得はブラウザ内のみ）。
